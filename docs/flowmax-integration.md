# ربط Flowmax

ربط مستقل يرسل الردود المعتمدة من لوحة النماذج إلى Flowmax.

- يعمل عبر API فقط، دون ربط قاعدتي البيانات.
- لا يُرسل أي رد قبل اعتماده صراحة من مستخدم يملك مراجعة الردود.

> **الحالة الحالية: الربط غير مُفعّل في الاستضافة (`FLOWMAX_ENABLED=false`).**
> يحتاج نقاط التكامل الجديدة في Flowmax (أدناه). نُفذت واختُبرت محليًا، ولم تُنشر على أي بيئة Flowmax.

## التغيير في Flowmax (ضروري لمنع التكرار)

البحث برمز قبل الإنشاء لا يمنع التكرار تحت التزامن أو بعد ضياع الاستجابة. لذلك أُضيفت إلى Flowmax:

- **سجل تكامل** بقيد فريد على مستوى قاعدة البيانات.
- **نقاط تكامل مخصصة** تستخدم خدماته الحالية دون تجاوز قواعد التحقق والنشر.

**التعديل كاملًا (9 ملفات) في [`docs/flowmax/forms-integration.patch`](flowmax/forms-integration.patch).** يُطبق على `backend/` بـ `git apply`.

| الملف                                                                            | الغرض                                                                                      |
| -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| `database/migrations/2026_10_15_000001_create_integration_intakes_table.php`     | جدول `integration_intakes`، فريد على `(integration_user_id, source_key)`                   |
| `app/Models/IntegrationIntake.php`                                               | النموذج                                                                                    |
| `app/Modules/FormsIntegration/Services/FormsIntegrationService.php`              | المطالبة بالمفتاح والإنشاء في معاملة واحدة، مع إعادة المعاملة عند تعارض الأقفال (deadlock) |

### نقاط التكامل

تتطلب حساب مشرف بصلاحية `integrations.forms` وحدها، ورمز Sanctum له.

| المسار                                                           | الوظيفة                                      |
| ---------------------------------------------------------------- | -------------------------------------------- |
| `POST /api/admin/integrations/forms/offers`                      | إنشاء مسودة عقار بالمفتاح `source_key`       |
| `POST /api/admin/integrations/forms/demands`                     | إنشاء طلب عقار بالمفتاح `source_key`         |
| `POST /api/admin/integrations/forms/offers/{source_key}/media`   | `media_key` و`kind` (`image`/`video`) والملف |
| `POST /api/admin/integrations/forms/offers/{source_key}/publish` | النشر بـ `PropertyService::publish`          |
| `GET /api/admin/integrations/forms/records/{source_key}`         | الحالة الحالية                               |

**سلوك المفتاح:**

- المفتاح نفسه بالمحتوى نفسه يعيد السجل نفسه (`replayed: true`).
- المفتاح نفسه بمحتوى مختلف يُرفض بـ `409 integration_key_conflict`.
- كل حساب تكامل يرى سجلاته فقط.

**الاستجابة لا تحتوي بيانات تواصل.** تحتوي:

- `id`.
- `reference`.
- `status`.
- `is_public`: منشور وظاهر في الكتالوج.
- `detail_url`: رابط صفحة التفاصيل في موقع Flowmax. يُبنى من `FRONTEND_URL` ومسارات الواجهة المؤكدة في كوده:
  - `frontend/website/app/property/[id]`.
  - `frontend/website/app/properties/demands/[reference]`.

### نشر تحديث Flowmax

1. يُطبَّق في بيئة Flowmax تجريبية منفصلة أولًا، ثم `php artisan migrate` (إضافة جدول فقط).
2. ثم تشغيل اختبارات `tests/Feature/FormsIntegration`.
3. **لا يُنشر على الإنتاج تلقائيًا.**

**ملاحظة سابقة لهذا التعديل:** تثبيت Flowmax جديد على MySQL يفشل في migration موجودة:

- الملف: `2026_07_28_000001_create_property_demand_marketplace_tables.php`.
- السبب: اسم فهرس طوله 79 حرفًا، وحد MySQL 64.
- لم يُعدَّل لأنه خارج نطاق الربط، لكنه يلزم معالجته قبل أي بيئة Flowmax جديدة على MySQL.

## إعداد منصة النماذج

### المتغيرات

تُضبط في Coolify فقط.

| المتغير                    | ملاحظة                                                         |
| -------------------------- | -------------------------------------------------------------- |
| `FLOWMAX_ENABLED`          | `false` افتراضيًا.                                             |
| `FLOWMAX_API_BASE_URL`     | أصل API لـ Flowmax؛ `https` إلزامي في الإنتاج.                 |
| `FLOWMAX_SERVICE_TOKEN`    | **سر**: رمز حساب التكامل `integrations.forms`، لا حساب المدير. |
| `FLOWMAX_TIMEOUT_MS`       | الافتراضي 15000.                                               |
| `FLOWMAX_MEDIA_TIMEOUT_MS` | الافتراضي 300000.                                              |

### ربط الأسئلة بالحقول

من صفحة النموذج: زر «ربط Flowmax» (صلاحية تعديل النماذج).

- **المصدر:** لكل حقل سؤال من آخر إصدار منشور، أو قيمة ثابتة.
- **حقول الاختيار:** تُطابق الأسماء العربية الشائعة تلقائيًا، مع جدول تحويل اختياري.
- **الحقول المطلوبة:**
  - **للعرض:** العنوان، الوصف، المدينة، الحي، السعر، رمز التصنيف، معرّف المطور، عقد الوساطة وتاريخه، رخصة فال.
  - **للطلب:** النوع، الغرض، المدينة، الميزانية، الجوال، موافقة المرسل، إصدار نص الموافقة.

## المراحل الثلاث

1. **الاعتماد** (`RESPONSES_REVIEW`):
   - قبل الاعتماد تعرض الصفحة الحقول الناقصة والمرفقات التي لا يقبلها Flowmax وسبب كل منها:
     - الصور: JPG/PNG/WEBP حتى 10MB و25 صورة.
     - الفيديو: MP4/MOV/WebM حتى 100MB و5 فيديوهات.
   - **الاعتماد ممنوع** (422) حتى تُكتمل البيانات، وحتى تُعالج المرفقات غير المتوافقة أو تُستبعد صراحة.
   - الاستبعاد يُسجَّل باسم المراجع وسببه في سجل التكامل والتدقيق.
   - عند النجاح، في معاملة واحدة: لقطة الطلب، وحالة الرد «مقبول»، والتدقيق.
2. **الإرسال** (في الخلفية):
   - إنشاء السجل بالمفتاح `lawha:response:{responseId}`.
   - ثم كل مرفق بمفتاحه `…:file:{fileId}`.
   - يُحفظ لكل مرفق حالته (نُقل، فشل، مستبعد) ومعرّفه في Flowmax وخطؤه.
   - فشل أي مرفق يجعل الحالة «فشل الإرسال» مع زر «إعادة المحاولة»، ولا يُعرض الرد كأنه أُرسل بالكامل.
3. **النشر:**
   - **العرض:** زر «نشر في Flowmax» بعد اكتمال الإرسال فقط، وبقواعد النشر في Flowmax.
     - الفشل يحفظ المعرّف والسبب، مثل «متطلبات النشر في Flowmax غير مكتملة: images»، ويُعرض زر إعادة المحاولة.
   - **الطلب:** يُنشر من مراجعة Flowmax، ثم «تحديث الحالة من Flowmax».

**رابط التفاصيل:** يُعرض للإدارة دائمًا مع بيان «غير منشور بعد». **المشاركة لا تظهر إلا بعد تأكيد Flowmax أن السجل منشور وظاهر** (`is_public`).

### منع التكرار

- **في منصة النماذج:** سجل واحد لكل رد بقيد فريد، فالاعتمادات المتزامنة تنتج سجلًا واحدًا.
- **في Flowmax:** القيد الفريد `(integration_user_id, source_key)` مع قفل الصف.
  - طلبات متزامنة، أو إعادة بعد ضياع الاستجابة، تعيد السجل نفسه.
  - ينطبق ذلك على العقار والطلب وكل مرفق.
- **انهيار العملية أثناء الإرسال أو النشر:** عند التشغيل التالي يتحول إلى «فشل» قابل لإعادة المحاولة.
