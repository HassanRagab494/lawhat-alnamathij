# ربط Flowmax

ربط مستقل يرسل الردود المعتمدة من لوحة النماذج إلى Flowmax.

- يعمل عبر API Flowmax فقط؛ لا ربط بين قاعدتي البيانات.
- لا يُرسل أي رد قبل اعتماده صراحة من مستخدم يملك صلاحية مراجعة الردود.

## ما يُنشأ في Flowmax

| نوع العملية | المسار في Flowmax                                    | النتيجة                                                 | الرابط المحفوظ                                             |
| ----------- | ---------------------------------------------------- | ------------------------------------------------------- | ---------------------------------------------------------- |
| عرض         | `POST /api/admin/properties` ثم `/images` و`/videos` | مسودة عقار (ونشرها إن ضُبط `FLOWMAX_AUTO_PUBLISH=true`) | `{FLOWMAX_PUBLIC_SITE_URL}/property/{id}`                  |
| طلب         | `POST /api/admin/property-demands`                   | طلب عقار بحالة «قيد المراجعة»                           | `{FLOWMAX_PUBLIC_SITE_URL}/properties/demands/{reference}` |

المرجع في Flowmax:

- `backend/docs/api/property-listing-fields.md`
- `backend/docs/property-demand-marketplace-api.md`
- `backend/routes/api/admin.php`

مسودة العقار لا تظهر للزوار حتى تُنشر في Flowmax، وتعرض الواجهة ذلك بجانب الرابط.

## الإعداد

### حساب التكامل في Flowmax

أنشئ في Flowmax مشرفًا مخصصًا للتكامل، ولا تستخدم حساب المدير الرئيسي:

- بصلاحية `properties.manage` (للعروض).
- و`property-demands.manage` (للطلبات) فقط.

ثم أصدر له رمز Sanctum، فهذا هو `FLOWMAX_SERVICE_TOKEN`.

### متغيرات البيئة

تُضبط في Coolify فقط، ولا تُكتب في أي ملف في Git.

| المتغير                    | ملاحظة                                              |
| -------------------------- | --------------------------------------------------- |
| `FLOWMAX_ENABLED`          | `false` افتراضيًا.                                  |
| `FLOWMAX_API_BASE_URL`     | أصل API لـ Flowmax؛ `https` إلزامي في الإنتاج.      |
| `FLOWMAX_SERVICE_TOKEN`    | **سر** (Is Secret). لا يُسجَّل ولا يظهر في الأخطاء. |
| `FLOWMAX_PUBLIC_SITE_URL`  | أصل موقع Flowmax العام لبناء روابط العقار والطلب.   |
| `FLOWMAX_TIMEOUT_MS`       | مهلة طلبات JSON. الافتراضي 15000.                   |
| `FLOWMAX_MEDIA_TIMEOUT_MS` | مهلة رفع كل ملف وسائط. الافتراضي 300000.            |
| `FLOWMAX_AUTO_PUBLISH`     | نشر العقار بعد إنشائه. الافتراضي `false`.           |

### ربط الأسئلة بحقول Flowmax

من صفحة النموذج: زر «ربط Flowmax»، ويتطلب صلاحية تعديل النماذج.

**مصدر كل حقل:** سؤال من آخر إصدار منشور (بمعرّفه المنطقي الثابت عبر الإصدارات)، أو قيمة ثابتة.

**حقول الاختيار:** تُطابق تلقائيًا الأسماء العربية الشائعة، مثل شقة ⇒ `apartment` وبيع ⇒ `sale` وعرض/طلب. ويمكن إضافة جدول تحويل بصيغة «نص الإجابة = قيمة Flowmax».

| ---------------------------- | ----------- | ----------- | ---------------------------------------- |
| نوع العملية                  | ✓           | ✓           | عرض أو طلب                               |
| العنوان                      | ✓           |             |                                          |

**البيانات الخاصة** تُرسل إلى حقول Flowmax الإدارية فقط:

- العرض: `contact_phone`، والاسم في `listing_notes`.
- الطلب: `requester_name` و`requester_phone`.

ولا تدخل نص المشاركة أبدًا.

## الاعتماد والإرسال

1. في تفاصيل الرد: «اعتماد وإرسال إلى Flowmax»، ويتطلب `RESPONSES_REVIEW` في الواجهة والـ API.
2. **التحويل حتمي:** يُبنى الطلب من الإجابات وفق الربط.
   - إن نقص حقل مطلوب أو كانت قيمة غير صالحة، يُرفض الاعتماد بـ `422 FLOWMAX_INCOMPLETE`.
   - تظهر رسالة عربية لكل حقل، مثل ««المدينة»: الإجابة مطلوبة لإنشاء العقار.».
   - لا يُحفظ شيء ولا تتغير الحالة.
3. **عند النجاح:** في معاملة واحدة:
   - تُحفظ لقطة الطلب.
   - تتحول حالة الرد إلى «مقبول» مع سجلها.
   - تُسجَّل العملية في التدقيق.
4. **الإرسال يتم في الخلفية:** `pending` ⇒ `sending` ⇒ `sent` أو `failed`، والواجهة تتحدث تلقائيًا.
5. **عند الفشل:** يظهر خطأ مختصر وزر «إعادة المحاولة»، بالصلاحية نفسها.

**يُحفظ لكل رد (جدول `flowmax_syncs`):**

- الحالة.
- معرّف Flowmax ومرجعه.
- الرابط.
- وقت الإرسال.
- آخر خطأ مختصر.
- عدد المحاولات.
- ما أُرسل من الوسائط وما تُخطي.

### منع التكرار

- **مفتاح ثابت لكل رد:** `lawha-{responseId}`، وسجل واحد لكل رد بقيد فريد. تكرار الاعتماد يعيد الحالة نفسها.
- **العرض:** Flowmax لا يدعم مفتاح منع التكرار عند إنشاء العقار، فيُرسل المفتاح في `platform_code` (مرجع المنصة الخارجية).
  - يُحفظ معرّف العقار فور إنشائه، فلا تنشئ إعادة المحاولة عقارًا ثانيًا.
  - إن انقطع طلب الإنشاء دون نتيجة (مهلة أو انقطاع أو خطأ 5xx)، يُعلَّم «ملتبسًا». المحاولة التالية تبحث في Flowmax عن عقار بنفس `platform_code` قبل أي إنشاء.
- **الطلب:** Flowmax يدعم `idempotency_key`، فإعادة الإرسال تعيد الطلب الأصلي.
- **الوسائط:** كل ملف أُرسل يُحفظ، فلا يُعاد عند إعادة المحاولة.
  - الصور حتى 10MB والفيديو حتى 100MB (حدود Flowmax)، وما يتجاوزها يُتخطى ويُذكر عدده.
  - تُرسل بالتدفق وباسم مولّد، لا الاسم الأصلي.
- **انهيار العملية أثناء الإرسال:** عند التشغيل التالي يتحول السجل إلى «فشل» قابل لإعادة المحاولة، مع البحث قبل الإنشاء.

**قيد معروف:** إن انقطع رفع ملف وسائط بعد أن استلمه Flowmax، فقد تتكرر تلك الصورة أو الفيديو عند إعادة المحاولة. العقار نفسه لا يتكرر.

## المشاركة

تظهر بعد نجاح الإرسال فقط، لمن يملك عرض الردود، وفيها ثلاثة أزرار:

- «مشاركة العقار»: مشاركة النظام، أو نسخ النص إن لم تتوفر.
- «نسخ الرابط».
- «مشاركة واتساب»: `https://wa.me/?text=` مع النص مرمّزًا بـ `encodeURIComponent`.

**يحتوي النص:**

- العنوان.
- نوع العرض أو الطلب والغرض والنوع.
- المدينة والحي.
- السعر أو الميزانية إن وجدت.
- الرابط.

**يُبنى من لقطة آمنة خالية من:**

- اسم المالك.
- الجوال.
- الملاحظات الداخلية.

ولا تُوضع أي بيانات خاصة في رابط.

## الأمان والسجلات

- الرمز في ترويسة `Authorization` فقط.
- الطلبات بلا تحويل (`redirect: error`) وبمهلة.
- **الأخطاء المحفوظة والمعروضة مختصرة:** رمز الحالة وأسماء الحقول المرفوضة فقط، دون قيمها أو رسائل Flowmax.
- **سجلات الخادم:** معرّف السجل ونوع الفشل فقط، دون الرمز أو بيانات المالك أو محتوى الطلب.
