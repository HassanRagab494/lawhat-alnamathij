# لوحة النماذج

منصة عربية لإنشاء النماذج وإدارة الردود لشركة واحدة.

- **المرحلة الأولى:** تسجيل الدخول والجلسات، المستخدمون والصلاحيات، وإدارة بيانات النماذج الأساسية.
- **المرحلة الثانية:** محرر أسئلة المسودة (8 أنواع، إعدادات وترتيب وحفظ ذري ومنع الكتابة المتزامنة) ومعاينة لا تحفظ أي إجابة.
- **المرحلة الثالثة:** نشر إصدارات ثابتة، ورابط عام `/f/<publicId>` يعبّئه الزائر دون حساب، واستقبال الردود وحفظها مع رقم مرجعي.
- **المرحلة الرابعة:** إدارة الردود: قائمة بالبحث والفلترة والترقيم، تفاصيل الرد كما في إصداره، تغيير الحالة مع سجل مستقل، وتصدير CSV.
- **المرحلة النهائية:** رفع الملفات الفعلي (تحقق من المحتوى وفحص ClamAV وتخزين خاص وتنزيل بصلاحية مستقلة)، والنسخ الاحتياطي المشفر والاستعادة، وتأمين التشغيل.

لا توجد إشعارات ولا أسئلة شرطية ولا تصدير XLSX.

| الجزء              | التقنية                                                             |
| ------------------ | ------------------------------------------------------------------- |
| الواجهة `apps/web` | Next.js 15 (App Router) + TypeScript + Tailwind CSS 4               |
| الـ API `apps/api` | NestJS 11 + TypeScript                                              |
| قاعدة البيانات     | MySQL 8.4 عبر Prisma 6 (migrations في `apps/api/prisma/migrations`) |
| مدير الحزم         | npm workspaces مع `package-lock.json`                               |

## المتطلبات

- Node.js 20.19 أو أحدث (يُفضّل 22 LTS) و npm 10+
- Docker مع Compose v2 **أو** MySQL 8.x مثبت محليًا

## التشغيل المحلي من نسخة جديدة

```bash
# 1) تثبيت الحزم (يولّد Prisma Client تلقائيًا)
npm ci

# 2) الإعدادات: انسخ المثال ثم غيّر كلمات المرور المحلية
cp .env.example .env

# 3) تشغيل MySQL (ينشئ أيضًا lawha_shadow لمستخدم التطبيق، وlawha_test بحساب اختبار مستقل)
npm run db:up

# 4) تطبيق migrations
npm run db:migrate

# 5) إنشاء مدير النظام الأول (تُطلب كلمة المرور بشكل مخفي مرتين)
npm run admin:create -- --username admin --display-name "مدير النظام"

# 6) تشغيل الـ API والواجهة (في طرفيتين)
npm run dev:api     # http://localhost:4000/api  — التوثيق: http://localhost:4000/api/docs
npm run dev:web     # http://localhost:3000
```

ثم افتح `http://localhost:3000` وسجّل الدخول بحساب المدير.

> **MySQL مثبت على Windows بدون Docker وبدون صلاحيات مدير:** بعد إنشاء `.env` شغّل
> `powershell -ExecutionPolicy Bypass -File scripts/mysql-local.ps1 init` مرة واحدة (ينشئ مجلد بيانات في
> `%LOCALAPPDATA%lawha-mysql` ويستمع على 127.0.0.1 فقط، وينشئ القواعد الثلاث والمستخدم من قيم `.env`)،
> ثم `start` أو `stop` أو `status` لاحقًا بدل `npm run db:up`.

> بدون Docker يدويًا: أنشئ في MySQL قاعدة `lawha` (وقاعدتي `lawha_test` و`lawha_shadow` إن أردت الاختبارات
> أو إنشاء migrations جديدة) ومستخدمًا له صلاحيات عليها، وعدّل `DATABASE_URL` و`TEST_DATABASE_URL`
> و`SHADOW_DATABASE_URL` في `.env`. اضبط المنطقة الزمنية للخادم على UTC أو اتركها؛ Prisma يخزّن UTC دائمًا.

## إنشاء المدير الأول

```bash
npm run admin:create -- --username <اسم المستخدم> --display-name "<الاسم الظاهر>"
```

- كلمة المرور تُكتب في الطرفية بشكل مخفي مرتين، ولا تظهر في سجل الأوامر.
- للأتمتة فقط: يمكن تمريرها لمرة واحدة عبر متغير البيئة `INITIAL_ADMIN_PASSWORD` لنفس الأمر.
- يرفض الأمر العمل إذا وُجد مدير نظام مسبقًا، ويطبق سياسة كلمة المرور (10 أحرف على الأقل، ولا تحتوي اسم المستخدم).
- يُسجَّل الإنشاء في `audit_logs` بالإجراء `user.bootstrap_admin`.
- لا يوجد أي حساب افتراضي أو كلمة مرور ثابتة في الكود.

## أوامر التحقق

```bash
npm run format:check   # Prettier
npm run typecheck      # tsc للتطبيقين
npm test               # اختبارات الوحدة (لا تحتاج قاعدة بيانات)
npm run build          # بناء التطبيقين
npm run check          # كل ما سبق
npm run test:e2e       # اختبارات التكامل على MySQL حقيقية عبر TEST_DATABASE_URL
npm run openapi:export # إعادة توليد docs/openapi.json
```

اترك `ALLOW_TEST_DATABASE_RESET` فارغًا في `.env` ومرّره لأمر الاختبار نفسه بعد مراجعة الهدف، مثل:
`ALLOW_TEST_DATABASE_RESET=lawha_test npm run test:e2e`.

`npm run test:e2e` يمسح `TEST_DATABASE_URL` ويطبق migrations من الصفر، ثم يختبر دورة HTTP → NestJS → Prisma → MySQL
كاملة (الدخول، الصلاحيات، إبطال الجلسات، النماذج، التزامن، إعادة التشغيل). يرفض العمل إذا كانت قاعدة الاختبار هي نفسها `DATABASE_URL`.

## محرر النموذج (المرحلة الثانية)

- صفحة النموذج `/forms/:id` فيها تبويبا «المحرر» و«المعاينة». صاحب صلاحية العرض فقط يرى «الأسئلة» للقراءة و«المعاينة».
- الأنواع: إجابة قصيرة، فقرة، اختيار واحد، اختيار متعدد، قائمة منسدلة، رقم، تاريخ، رفع ملفات (إعداد ومعاينة فقط).
- زر واحد «حفظ التغييرات» يحفظ العنوان والوصف والأسئلة والخيارات والترتيب في معاملة واحدة عبر `PUT /api/forms/:id/draft`.
- السؤال الناقص يبقى في المحرر مع رسالة بجانبه، ولا يُرسل للخادم حتى يكتمل.
- عند تعارض المراجعة تبقى التعديلات المحلية، ويُعرض محتوى الخادم الأحدث مع خياري «الإبقاء على تعديلاتي لمراجعتها» أو «تحميل نسخة الخادم».
- تحذير عند مغادرة الصفحة مع وجود تغييرات غير محفوظة: إغلاق التبويب أو تحديثه، الروابط الداخلية، وزرا الرجوع والتقدم داخل التطبيق (`apps/web/src/lib/history-guard.ts`، دون إضافة مدخلات للسجل).

**الحدود المركزية** (أسئلة، خيارات، أطوال، أرقام، تواريخ، ملفات): `apps/api/src/forms/questions/limits.ts`،
وتستخدم الواجهة نسخة مطابقة في `apps/web/src/lib/question-limits.ts`، ويفشل الاختبار `question-limits.test.ts` إن اختلفتا.
القيم الحالية: 100 سؤال، و2–50 خيارًا، وعنوان سؤال 300 حرف، ووصف مساعد 1000، ونص خيار 200، وطول إجابة قصيرة حتى 500 وفقرة حتى 10000،
وأرقام بقيمة مطلقة حتى 10¹²، وتواريخ بين 1900-01-01 و2100-12-31، وملفات حتى 25 ميغابايت و10 ملفات من أنواع: PDF وJPG وPNG وWEBP وDOCX وXLSX وTXT.

حجم جسم طلب حفظ المسودة حد إجمالي مستقل مقداره 4 ميغابايت (بقية المسارات 100KB)، يُطبق مع حدود الأحرف ولا يحل محلها؛ ما يتجاوزه يُرفض بـ 413 برسالة عربية وتبقى التعديلات في المحرر.

تفاصيل الـ API والإعدادات حسب النوع: [docs/api.md](docs/api.md).

## النشر والرابط العام (المرحلة الثالثة)

- بطاقة «النشر والاستقبال» في صفحة النموذج تعرض:
  - حالة النشر وآخر إصدار.
  - شارة «تغييرات محفوظة غير منشورة».
  - حالة الاستقبال.
  - الرابط العام مع زر نسخ.
- **النشر:** زر «نشر النموذج» يعرض ملخصًا ويطلب تأكيدًا.
  - ينشر **المسودة المحفوظة فقط**. مع وجود تعديلات غير محفوظة يُعطّل الزر حتى الحفظ.
  - يُمنع نشر نموذج بلا أسئلة أو فيه سؤال رفع ملفات، مع شرح السبب.
  - أول نشر يسأل صراحة: هل يُفتح الاستقبال فورًا؟ النشرات اللاحقة تحافظ على حالة الاستقبال.
  - الإصدار المنشور ثابت: تعديل المسودة أو حذف أسئلتها لا يغيّره ولا يغيّر الردود المحفوظة عليه. لا يوجد إلغاء نشر.
- **الاستقبال:** فتحه وإغلاقه بتأكيد واضح. الأرشفة تغلقه، والاستعادة لا تعيد فتحه.
- **الصلاحيات الجديدة:** «نشر النماذج» (`FORMS_PUBLISH`) و«فتح وإغلاق استقبال الردود» (`FORMS_INTAKE`).
  - المدير يملكهما تلقائيًا، والمشرف بمنح صريح فقط.
  - فتح الاستقبال مع أول نشر يتطلب الصلاحيتين معًا.
- **الصفحة العامة** `/f/<publicId>`:
  - بلا تسجيل دخول ولا أدوات إدارة، وتعرض العنوان والوصف والأسئلة فقط.
  - زر «إرسال» محمي من النقر المزدوج، وأخطاء عربية بجانب كل سؤال.
  - الإجابات تبقى في الصفحة عند فشل الشبكة أو التحقق، ولا تُستخدم localStorage ولا أدوات تحليل.
  - عند النجاح يظهر رقم مرجعي، ولا تُوضع الإجابات في الرابط.
  - **إذا نُشر إصدار أحدث أثناء التعبئة:** يُرفض الإرسال برسالة واضحة، وتبقى الإجابات، ويُعرض زر «تحديث النموذج».
    - التحديث ينقل الإجابات للأسئلة الموجودة بمفاتيحها المنطقية.
    - لا يُرسل شيء تلقائيًا.
- **منع التكرار:** مفتاح عشوائي لكل محاولة تعبئة. إعادة المحاولة بعد انقطاع تعيد الرقم المرجعي الأصلي ولا تنشئ ردًا ثانيًا.
- **حدود مكافحة الإساءة:**
  - حجم طلب الرد 512 كيلوبايت.
  - 10 إرسالات في الدقيقة لكل IP، و120 لكل نموذج.
  - لا CAPTCHA.
  - **بند مفتوح قبل النشر:** تزوير `X-Forwarded-For` يتجاوز حد IP إذا وصل الزائر إلى Next.js مباشرة. الإعداد الصريح المطلوب والاختبار عبر الوكيل الفعلي في [docs/trust-boundary.md](docs/trust-boundary.md).

## إدارة الردود (المرحلة الرابعة)

- **الوصول إلى الردود:**
  - من قائمة النماذج: رابط «الردود» بجانب كل نموذج منشور.
  - من صفحة النموذج: زر «عرض الردود».
  - يظهر الرابطان لمن يملك «عرض الردود» فقط.
- **القائمة** `/forms/:id/responses`:
  - الأعمدة: الرقم المرجعي، ووقت الإرسال بتوقيت الرياض، ورقم الإصدار، والحالة.
  - البحث بالرقم المرجعي، وفلاتر الحالة والتاريخ من/إلى والإصدار، والترتيب، والترقيم.
  - الفلاتر محفوظة في الرابط وتبقى عند العودة من التفاصيل.
  - جدول على الشاشات الكبيرة وبطاقات على الجوال.
- **التفاصيل:**
  - كل سؤال كما نُشر في إصدار الرد، والإجابة حسب نوعه.
  - الخيارات المختارة مميزة، والسؤال الاختياري الفارغ موضح.
  - سؤال الملفات برسالة أن الرفع غير متاح بعد.
  - يُعرض سجل الحالات، وتغيير الحالة متاح لمن يملك «مراجعة الردود».
  - كل النصوص تُعرض نصًا عاديًا دون HTML، ولا تظهر معرّفات داخلية.
- **الحالات:** جديد، قيد المراجعة، مقبول، مرفوض.
  - كل تغيير يُسجَّل في سجل مستقل بالحالتين والمستخدم والوقت.
  - إعادة الحالة نفسها لا تضيف سجلًا.
- **التصدير:** زر «تصدير CSV» لمن يملك «تصدير الردود».
  - يحترم الفلاتر الحالية ويمنع حقن الصيغ.
  - الحد 5000 صف و10 ميغابايت.
- **الصلاحيات الجديدة:**
  - «عرض الردود» (`RESPONSES_VIEW`، تتطلب عرض النماذج).
  - «مراجعة الردود وتغيير حالتها» (`RESPONSES_REVIEW`).
  - «تصدير الردود» (`RESPONSES_EXPORT`).
  - الأخيرتان تتطلبان عرض الردود. المدير يملكها تلقائيًا.
- **قاعدة البيانات:** مفاتيح مركبة تمنع ربط إجابة بسؤال أو خيار من إصدار آخر، أو ربط رد بإصدار من نموذج آخر.

التفاصيل في [docs/api.md](docs/api.md#إدارة-الردود-المرحلة-الرابعة).

## رفع الملفات والنسخ الاحتياطي (المرحلة النهائية)

**رفع الملفات:**

- **في الصفحة العامة:** يختار الزائر الملفات فيرى الاسم والحجم وتقدم الرفع ثم «جارٍ التحقق والفحص» ثم «جاهز» أو سبب الرفض بالعربية.
  - يمكنه إزالة ملف قبل الإرسال.
  - الإرسال ممنوع أثناء رفع أو فحص.
  - الإجابات تبقى عند فشل الرفع أو الإرسال.
- **على الخادم:**
  - جلسة تعبئة مجهولة قصيرة الصلاحية للإصدار الحالي.
  - كتابة بالتدفق إلى منطقة مؤقتة خاصة.
  - النوع من المحتوى الفعلي ويجب أن يطابق الامتداد.
  - DOCX/XLSX بفك فعلي بحدود ضد ZIP bomb.
  - رفض المشفر.
  - فحص ClamAV؛ تعطل الفاحص يعني الرفض مع إمكانية إعادة المحاولة.
  - تخزين باسم عشوائي في volume خاص، والـ API وحده يصل إليه.
  - التحقق من الملكية عند الإرسال وربط الملفات بالرد في المعاملة نفسها، مع تنظيف دوري للمؤقت المنتهي فقط.
- **في الإدارة:** الأسماء والأحجام في تفاصيل الرد، والتنزيل كمرفق بصلاحية «تنزيل ملفات الردود» (`RESPONSES_FILES_DOWNLOAD`)، وأسماء الملفات فقط في CSV.
- **التخزين:** خلف واجهة `FileStorage` قابلة للاستبدال بتخزين متوافق مع S3، والفاحص خلف `MalwareScanner`.
- **محليًا:** الرفع معطل ما لم يُضبط `CLAMAV_HOST` إلى clamd يعمل.

**النسخ الاحتياطي والاستعادة:** نسخة يومية مشفرة للقاعدة وملفات الردود مع manifest وتحقق اتساق، واحتفاظ 7 يومية و4 أسبوعية، وأداة استعادة إلى قاعدة منفصلة تتحقق من العلاقات وتجزئات الملفات. الدليل وخطة التراجع في [deploy/backup/README.md](deploy/backup/README.md).

## خارج النطاق حاليًا

التصدير بصيغة XLSX أو غير المتزامن، حذف الردود أو ملفاتها،
التصدير، الإشعارات، الأسئلة الشرطية، تعدد الشركات، الخدمات الخلفية والتكاملات، والنشر على أي سيرفر.
لا توجد في الواجهة روابط أو أزرار توحي بوجود هذه الوظائف. المعاينة لا تحتوي زر إرسال، والإرسال الحقيقي متاح فقط على الرابط العام.

### حماية قاعدة التكامل

يلزم DATABASE_URL صالحًا للمقارنة وTEST_DATABASE_URL باسم ينتهي بـ `_test`، وموافقة يدوية `ALLOW_TEST_DATABASE_RESET=lawha_test` تطابق الاسم حرفيًا. لا تضبط الموافقة لقواعد التطوير أو الإنتاج. يُرفض اسم القاعدة المطابق لقاعدة التطبيق حتى عبر مضيف أو منفذ مختلفين؛ اختلاف المستخدم وكلمة المرور ومعاملات الاتصال لا يثبت استقلال القاعدة. تُرفض معاملات تغيير وجهة الاتصال غير المدعومة، ويُرفض تعذر حل DNS. أسماء DNS المستعارة وNAT والأنفاق قد تشير لخادم واحد؛ لا يمكن استنتاج الهوية الفيزيائية يقينًا من URL أو DNS. يلزم حساب MySQL محدود إلى قاعدة الاختبار فقط، والتحقق الإداري من الهدف قبل الموافقة. لا يُنفذ reset دون هذه الشروط.
